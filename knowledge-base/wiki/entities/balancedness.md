# Сбалансированность

## Определение

Булева функция $f \in \mathcal{F}_n$ называется **сбалансированной** (уравновешенной), если её вес равен:
$$w(f) = 2^{n-1}.$$

Эквивалентно: при равномерном распределении входа выход равновероятен:
$$\mathbb{P}(f(x) = 0) = \mathbb{P}(f(x) = 1) = \tfrac{1}{2}.$$

## Связь с [[walsh-hadamard|ПУА]]

$f$ сбалансирована ⇔ $\hat{f}(0^n) = 0$.

Это частный случай критерия [[correlation-immunity|m-устойчивости]] при $m = 0$.

## Важное свойство для S-блоков

> [!info] Из общей литературы (не из 1-й курсовой)
> Все ненулевые компонентные функции $f_b(x) = \langle b, S(x)\rangle$ **биективной** S-функции автоматически сбалансированы.
>
> Это означает, что при генерации **биективного** S-блока ([[fisher-yates-shuffle|случайной перестановки]] или с её сохранением через swap-ходы) сбалансированность компонент достигается «бесплатно» — fitness-функция её не оптимизирует.
>
> Стандартный факт (Карле, 2021). Запланирован ingest для формального подтверждения — см. [[backlog]].

## Криптографический смысл

Если хотя бы одна компонента S-блока несбалансирована — соответствующий выходной бит шифра предсказуем с bias ≠ 0, что эксплуатируется:
- в **линейном криптоанализе** (Matsui) — через [[nonlinearity|линейные аппроксимации]];
- в **корреляционных атаках** на потоковых шифрах — см. [[correlation-immunity]].

Поэтому сбалансированность — **необходимое** условие криптографической применимости функции.

## Реализация

- `boolfunc/boolfunc.go:130` — `BoolFunc.Weight()`: popcount по упакованному вектору истинности `tvp []uint64`, $O(2^n / 64)$.
- `boolfunc/boolfunc.go:125` — `BoolFunc.IsBalanced()`: проверка $w(f) = 2^{n-1}$.
- `boolfunc/boolfunc.go:78` — `RandomBalanced(n)`: ставит $2^{n-1}$ единиц + shuffle.

Для S-блока отдельный метод проверки сбалансированности компонент не нужен — биективность достаточна (см. блок выше). Биективность проверяется в `sbox/sbox.go:58` — `SBox.IsBijective()`.
