# Эмпирические наблюдения SA для S-блоков 8×8

Факты, обнаруженные при настройке SA-генератора. Не из учебников — из собственных экспериментов с реализованной cost-функцией.

---

## Конфигурация наблюдений

- $n = 8$ (биективные S-блоки 8×8).
- Cost-функция: [[fitness-function-sbox|Clark-Jacob-Stepney]] с $X = 24$, $R = 3$.
- Calibration: probes = 1000, $p_0 = 0.8$.
- Дата: 2026-05-15.

---

## Hill Climbing — baseline

Один запуск HC из случайной биективной перестановки, 100K итераций.

| Метрика | Значение |
|---|---|
| Начальная cost | $\sim 2.7 \cdot 10^8$ |
| Начальная NL | 96–100 |
| Финальная NL | **94–104**, медиана ~ 98 |
| Accepted ratio | ~0.1% |
| Сходимость | застревает быстро |

**Парадокс:** cost уменьшается, но NL может **ухудшаться**. Cost CJS оптимизирует **распределение** $|W|$, NL зависит **только от максимума**. Эти две вещи не строго эквивалентны.

Вывод: чистый HC недостаточен. SA с температурой нужен, чтобы выйти из локальных минимумов CJS, где NL «застывает».

## Распределение initial cost из random start

10 случайных биективных перестановок, каждая получена через `rand.Shuffle`:

| Run | Initial cost |
|---|---|
| 1  | $2.70 \cdot 10^8$ |
| 2  | $2.70 \cdot 10^8$ |
| 3  | $2.72 \cdot 10^8$ |
| 4  | $2.70 \cdot 10^8$ |
| 5  | $2.70 \cdot 10^8$ |
| 6  | $2.70 \cdot 10^8$ |
| 7  | $2.69 \cdot 10^8$ |
| 8  | $2.72 \cdot 10^8$ |
| 9  | $2.71 \cdot 10^8$ |
| 10 | $2.72 \cdot 10^8$ |

**Среднее**: $2.706 \cdot 10^8$, **разброс**: ~1%.

> [!info] Что это значит
> Cost случайной биективной перестановки практически **детерминирована** на масштабе нашей задачи. Распределение $|W|$ для random permutations концентрировано около типичного значения (теорема концентрации в большом размере).

**Практическое следствие:** статистические свойства random start стабильны, и калибровка $T_0$ один раз даёт работающую $T_0$ для **всех** запусков multi-start.

## Калибровка $T_0$ — стабильность

10 калибровок [[t0-calibration|по формуле]] $T_0 = -\langle|\Delta E|\rangle / \ln 0.8$, probes = 1000, из 10 разных random стартов:

| Run | $T_0$ |
|---|---|
| 1  | $1\,804\,823$ |
| 2  | $1\,505\,487$ |
| 3  | $1\,631\,410$ |
| 4  | $1\,359\,871$ |
| 5  | $1\,609\,123$ |
| 6  | $1\,392\,439$ |
| 7  | $2\,008\,902$ |
| 8  | $1\,256\,571$ |
| 9  | $1\,440\,259$ |
| 10 | $1\,233\,963$ |

**Среднее**: $1.524 \cdot 10^6$, **стандартное отклонение**: $\sim 2.3 \cdot 10^5$ (~15%).

**Практическая рекомендация:** взять **$T_0 = 2 \cdot 10^6$** — округление вверх со страховкой. Перекалибровать перед каждым multi-start запуском **не нужно** — оценка стабильна.

## $T_0$ из AES vs из random — неинтуитивный результат

| Стартовая точка | Cost | $T_0$ |
|---|---|---|
| AES (NL=112) | (большая, не измерена точно) | $\sim 1.5 \cdot 10^7$ |
| Random | $\sim 2.7 \cdot 10^8$ | $\sim 1.5 \cdot 10^6$ |

**$T_0$ из AES в 10 раз больше, хотя cost меньше.**

> [!warning] Контринтуитивное наблюдение
> AES — локальный (вероятно глобальный) минимум CJS-cost. Любой swap из AES — ухудшение, и среднее $|\Delta E|$ ухудшений из AES **больше**, чем из random.
>
> Из random ухудшения **меньше по магнитуде**, потому что в широкой долине ландшафта градиент пологий.

**Следствие для практики:** калибровать $T_0$ нужно **из той точки, откуда будет стартовать SA**. Если SA из random — калибровать из random (мы так и делаем).

## Ожидаемые параметры SA

На основе наблюдений выше — стартовые параметры для первого реального SA-запуска:

| Параметр | Значение |
|---|---|
| $T_0$ | $2 \cdot 10^6$ |
| $\alpha$ | 0.99 |
| $M$ (длина плато) | 1000 |
| $T_{min}$ | 1 |
| $E_{target}$ | 0 |
| `MaxIter` | $5 \cdot 10^6$ |

Расчётная длительность одного запуска: $\sim 1.45 \cdot 10^6$ swap'ов.
