# Hill Climbing (восхождение к вершине)

Простейший алгоритм локального поиска: всегда переходит **только** в улучшающие соседние состояния, **никогда** не принимает ухудшения.

## Алгоритм

```
S ← начальное состояние
повторять:
    S' ← random_neighbor(S)
    если E(S') < E(S):
        S ← S'
    иначе:
        S остаётся
пока есть улучшения / лимит итераций
```

## Связь с [[simulated-annealing]]

Hill climbing — это **SA при $T = 0$**. Правило Метрополиса вырождается:
$$P(\text{accept } \Delta E \geq 0) = e^{-\Delta E / T} \to 0 \text{ при } T \to 0.$$

То есть улучшения принимаются всегда, ухудшения — никогда.

## Сильные и слабые стороны

| Плюсы | Минусы |
|---|---|
| Простой в реализации | Застревает в **любом** локальном минимуме |
| Не нужны гиперпараметры | Не может выбраться из плато |
| Быстрая сходимость | Часто даёт плохое финальное качество |

## Зачем нужен в нашем проекте

В нашей работе hill climbing — это **baseline**:
1. Если HC не сходится — значит проблема с cost-функцией (нет градиента, плохая нормализация). SA её не починит.
2. SA должен давать **заметно лучше** HC. Если разница в результате 1-2% — schedule температуры не помогает, что-то не так.
3. Реализация HC в 5 строк → можно проверить cost-функцию за минуту.

См. [[fitness-function-sbox]] про конкретную cost.

## HC как вторая фаза в SA+HC

Ключевое применение HC в проекте — **не baseline**, а **вторая фаза** двухфазного алгоритма SA+HC (Clark-Jacob-Stepney 2005).

### Почему одиночный SA не достигает NL=112

Пространство биективных 8×8 S-блоков ($256! \approx 8.6 \times 10^{506}$) имеет барьер: одиночный SA стабильно достигает NL=100–104 и застревает. Этот барьер — следствие структуры ландшафта, а не выбора cost-функции.

### Двухфазная схема

```
Фаза 1 — SA с cost-функцией (MinMaxWalsh или CJS):
    стартовая точка: random биективная перестановка
    цель: найти S-блок с NL ≥ 100–104 (хорошая стартовая точка)

Фаза 2 — HC непосредственно по NL:
    принимать swap только если NL(S') > NL(S)
    запускать сотни тысяч итераций
    цель: дотащить с NL=104 до NL=112
```

### Почему это работает

HC из случайной точки достигает NL≈98–104 и застревает. HC из точки SA (NL≈104) находится **ближе к бассейну притяжения NL=112** — там больше улучшающих swap-соседей. CJS 2005 (Table III) показывает: SNLT (SA + HC по NL) достигает NL=112.

### HC по NL — конкретный алгоритм

```
S ← выходное состояние SA (NL ≈ 104)
повторять hcIter раз:
    i, j ← random из {0..255}, i ≠ j
    swap(S[i], S[j])
    если NL(S) > NL(S_prev):
        принять  // S_prev = S
    иначе:
        откатить swap(S[i], S[j])  // инволютивное — бесплатно
```

Единственное отличие от обычного HC — **метрика напрямую**, без cost-функции-посредника.
