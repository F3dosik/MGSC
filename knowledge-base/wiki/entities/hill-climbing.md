# Hill Climbing (восхождение к вершине)

Простейший алгоритм локального поиска: всегда переходит **только** в улучшающие соседние состояния, **никогда** не принимает ухудшения.

## Алгоритм

```
S ← начальное состояние
повторять:
    S' ← random_neighbor(S)
    если E(S') < E(S):
        S ← S'
    иначе:
        S остаётся
пока есть улучшения / лимит итераций
```

## Связь с [[simulated-annealing]]

Hill climbing — это **SA при $T = 0$**. Правило Метрополиса вырождается:
$$P(\text{accept } \Delta E \geq 0) = e^{-\Delta E / T} \to 0 \text{ при } T \to 0.$$

То есть улучшения принимаются всегда, ухудшения — никогда.

## Сильные и слабые стороны

| Плюсы | Минусы |
|---|---|
| Простой в реализации | Застревает в **любом** локальном минимуме |
| Не нужны гиперпараметры | Не может выбраться из плато |
| Быстрая сходимость | Часто даёт плохое финальное качество |

## Зачем нужен в нашем проекте

В нашей работе hill climbing — это **baseline**:
1. Если HC не сходится — значит проблема с cost-функцией (нет градиента, плохая нормализация). SA её не починит.
2. SA должен давать **заметно лучше** HC. Если разница в результате 1-2% — schedule температуры не помогает, что-то не так.
3. Реализация HC в 5 строк → можно проверить cost-функцию за минуту.

См. [[fitness-function-sbox]] про конкретную cost.
