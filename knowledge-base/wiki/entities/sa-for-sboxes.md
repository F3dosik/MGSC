# SA для генерации S-блоков — специфика и результаты

Применение [[simulated-annealing|SA]] к задаче генерации биективных 8×8 S-блоков имеет конкретные особенности, которые кардинально влияют на результат.

---

## Мутация: swap двух элементов

Единственная допустимая мутация — **случайная транспозиция** двух элементов таблицы подстановки:

```
выбрать i ≠ j ∈ {0..255} случайно
swap(S[i], S[j])
```

Это сохраняет биективность автоматически: таблица остаётся перестановкой. Все остальные мутации (замена одного элемента) нарушают биективность и требуют коррекции.

**Свойство инволютивности:** повторный swap тех же i, j возвращает исходное состояние. Это позволяет бесплатно откатывать шаг без хранения снапшотов. См. реализацию в `generate/state.go`.

---

## Пространство поиска

Пространство биективных 8×8 S-блоков — это $256!$ перестановок:

$$|BP(8)| = 256! \approx 8.6 \times 10^{506}$$

Из них криптографически сильных (NL=112, δ=4) — ничтожно мало. Любой SA работает в этом пространстве только через локальный поиск.

## Cost-функции и их ограничения

### CJS (Clark-Jacob-Stepney 2005)

$$\text{cost}(S) = \sum_{\beta \neq 0} \sum_{\omega \neq 0} \left||\hat{F}_\beta(\omega)| - X\right|^R$$

Оптимизированные параметры по литературе:

| Параметр | CJS 2005 | MDPI 2022 |
|---|---|---|
| X | {-4,...,4} (перебор) | **36** |
| R | 3 | **4** |
| α | не указан явно | **0.95** |
| T₀ | не указан явно | 20 000 |

> [!warning] Проблема CJS для биективных S-блоков
> CJS(X=0) имеет ландшафт, где AES (NL=112) стоит **дороже** случайного S-блока: cost(AES)≈5.35×10⁸ > cost(random)≈4.28×10⁸. Оптимизатор уходит от цели. Подробный анализ — в [[fitness-function-sbox#Почему CJS не ведёт к NL=112]].
> X=36 (MDPI 2022) даёт другой ландшафт и позволяет достичь NL=104.

### MinMaxWalsh и ThresholdNL

Реализованы в `generate/cost.go`. Правильные ландшафты (минимум в AES), но single SA всё равно застревает на NL=100. Причина — не в функции, а в структуре ландшафта: барьер между NL=100 и NL=112.

## Что достигает SA в одну фазу

| Подход | Лучший NL | Источник |
|---|---|---|
| HC из random | 98–104 | Millan 1998 |
| SA + CJS (наш эксперимент, X=0) | 98–100 | 2026-05-16 |
| SA + MinMaxWalsh (наш эксперимент) | 100 | 2026-05-17 |
| SA + CJS оптимизированный (X=36, R=4) | **104** | MDPI 2022 |
| SA + CJS (CJS 2005, лучший из 200 запусков) | **102** | CJS 2005 Table I |

**Вывод:** single SA для биективных 8×8 практически не выходит за NL=104. Стена реальная.

## Двухфазный SA + HC — путь к NL=112

Подход из CJS 2005, подтверждённый в дальнейшей литературе:

```
Фаза 1 — SA:
    запустить SA с CJS или MinMaxWalsh
    цель: найти стартовую точку с NL ≥ 100-104
    (лучше из N параллельных запусков)

Фаза 2 — HC по NL:
    hill-climbing непосредственно по NL(S)
    принимать swap только если NL(S') > NL(S)
    запускать сотни тысяч итераций
    цель: дотащить с NL=104 до NL=112
```

### Почему HC из хорошей стартовой точки работает

HC из random start достигает NL≈98-104 и застревает. Но HC из точки SA (NL≈104) находится **ближе к бассейну притяжения NL=112** — там больше улучшающих swap-соседей. Это эмпирический факт из CJS 2005 (Table III: SNLT достигает NL=112).

> [!todo] Нужна верификация: насколько вероятен HC к NL=112 из стартовой точки NL=104 vs NL=98? Нет своих данных, нужен эксперимент.

### Результаты CJS 2005 для двухфазного подхода

Из Table III статьи (8×8 биективные S-блоки, SNLT = SA + HC по NL):

| Метод | NL | AC |
|---|---|---|
| random + HC | 100–104 | — |
| SA + HC (NL target) | **112** | 40 |
| SA + HC (AC target) | 80 | 80 |

NL=112 при AC=40 — это уровень AES.
