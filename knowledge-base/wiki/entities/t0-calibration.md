# Калибровка начальной температуры $T_0$

Начальная температура — один из **двух самых критичных** гиперпараметров [[simulated-annealing|SA]] (второй — $\alpha$). Неправильно подобранная $T_0$ делает SA либо бесполезным, либо неэффективным.

---

## Почему калибровка нужна

В отличие от других гиперпараметров, $T_0$ **зависит от масштаба cost-функции**, который заранее неизвестен. Cost CJS для $n=8$ даёт значения порядка $10^8$ и swap-дельты порядка $10^5$, для другой cost-функции это могут быть десятки или миллионы.

### Что бывает, если ошибиться

| $T_0$ относительно cost | Поведение SA | Симптом в Results |
|---|---|---|
| **Слишком мала** ($T_0 \ll \langle\|\Delta E\|\rangle$) | Все ухудшения отвергаются с самого начала → SA = [[hill-climbing\|HC]] | `AcceptedUp ≈ 0`; результат не лучше HC |
| **Правильная** | Сначала свободное исследование, постепенный переход к спуску | `AcceptedUp / Accepted ≈ 0.5–0.8` в начале |
| **Слишком велика** ($T_0 \gg \langle\|\Delta E\|\rangle$) | Все swap'ы принимаются → случайное блуждание; полезная оптимизация начнётся после многих итераций охлаждения | `Accepted ≈ TotalIter`; результат как у случайной перестановки до позднего этапа |

То есть **диапазон правильных $T_0$ может быть очень узким**, особенно для cost-функций с большим динамическим диапазоном.

---

## Концепция — целевая acceptance rate $p_0$

Идея калибровки: вместо «подобрать $T_0$» — задать **долю ухудшений, которые должны приниматься на старте** ($p_0$). По умолчанию $p_0 = 0.8$, что означает:

> «Хочу, чтобы в начале SA принимались 80% предложенных ухудшающих swap'ов»

Это создаёт достаточный «термоэнергетический» простор для исследования, но не превращает SA в чистый random walk.

Типичные значения $p_0$:
- $0.5–0.7$ — для задач, где много локальных минимумов и нужно широкое исследование;
- $0.8–0.9$ — стандартный выбор;
- $0.95+$ — для очень многомерных задач (требует больше итераций).

---

## Вывод формулы

Acceptance criterion Metropolis:
$$P(\text{accept ухудшение } \Delta E > 0) = e^{-\Delta E / T}.$$

Хотим, чтобы для **типичного** $\Delta E$ (равного среднему $\langle|\Delta E|\rangle$ по ухудшениям) вероятность принятия равнялась $p_0$:
$$p_0 = e^{-\langle|\Delta E|\rangle / T_0}.$$

Логарифмируем и выражаем $T_0$:
$$\boxed{T_0 = -\frac{\langle|\Delta E|\rangle}{\ln p_0}}$$

Для $p_0 = 0.8$: $-1/\ln 0.8 \approx 4.48$, то есть $T_0 \approx 4.48 \cdot \langle|\Delta E|\rangle$.

> [!warning] Это аппроксимация
> Формула предполагает, что все ухудшения имеют примерно одинаковую $\Delta E$ (распределение узкое). На практике распределение $\Delta E$ может быть **широким** (особенно с $R > 1$ в [[fitness-function-sbox|CJS]]), и фактический acceptance rate может отличаться от $p_0$ в 2-3 раза. Тем не менее, формула даёт правильный **порядок** $T_0$, что критично.

## Алгоритм

```
вход:  state (начальное состояние), probes (число проб), p₀ (целевая acceptance rate)
выход: T₀

sum_dE ← 0
count  ← 0

для k = 1..probes:
    i, j, oldE ← state.RandomSwap()      # делаем swap
    ΔE ← state.Cost() - oldE
    если ΔE > 0:                          # учитываем только ухудшения
        sum_dE ← sum_dE + ΔE
        count  ← count + 1
    state.Swap(i, j)                      # ОТКАТЫВАЕМ — калибровка
                                          # не должна сдвигать state

если count = 0:
    вернуть 1.0                           # все swap'ы — улучшения, нетипично
                                          # fallback значение
mean_dE ← sum_dE / count
вернуть -mean_dE / ln(p₀)
```

### Зачем откат после каждого swap

Это критическая деталь. Если **не** откатывать, мы дрейфуем по пространству состояний во время калибровки, и:
1. Cost может уйти далеко от начального → среднее $\Delta E$ будет не репрезентативно.
2. После калибровки `state` окажется в случайной точке, не той, где будет стартовать SA.

С откатом — все probes делаются **из одной и той же стартовой точки**, что даёт корректную статистику для именно этой точки.

> [!note] Swap инволютивен — это и используется
> `state.Swap(i, j)` второй раз с теми же индексами возвращает state в исходное. Это бесплатный «undo» без хранения снапшотов. Поэтому калибровка не требует дополнительной памяти.

---

## Edge cases

### count = 0 — все swap'ы улучшения

Возможно только в **очень плохой** стартовой точке, где почти любой ход улучшает cost. На практике для случайной биективной S-функции и CJS-cost — никогда. Если случилось — `T₀ = 1.0` как разумный fallback (любое значение лучше, чем деление на 0).

Альтернатива: увеличить `probes` в надежде поймать хотя бы одно ухудшение. Но если их объективно нет — fallback нужен.

### count = probes — все swap'ы ухудшения

Тоже возможно — если стартовая точка близка к локальному минимуму. Формула работает корректно.

### Очень малое count (e.g., 2–3 из 100)

Среднее по 2-3 ухудшениям статистически ненадёжно. В этом случае стоит **увеличить probes** (1000+) или принять, что $T_0$ калибруется приблизительно.

## Практические рекомендации

| Параметр | Значение | Замечание |
|---|---|---|
| `probes` | 100–500 | 100 хватает для оценки порядка; 500 даёт более стабильную оценку |
| `p₀` | 0.8 | стандарт; можно 0.5 для агрессивного спуска, 0.9 для широкого исследования |
| Stage | Перед каждым SA-запуском | $T_0$ зависит от стартовой точки; калибровать заново при каждом запуске multi-start |

## Альтернативы

### Адаптивный SA

Вместо фиксированного $T_0$ — корректировать $T$ в процессе, следя за текущим acceptance rate. Если rate упал ниже целевого — повысить $T$. Сложнее в реализации, не всегда даёт лучше.

### Ручной подбор

Запустить SA с тремя $T_0$: $\langle\Delta E\rangle$, $5\langle\Delta E\rangle$, $20\langle\Delta E\rangle$. Посмотреть `AcceptedUp / Accepted` на старте — выбрать тот, где соотношение ≈ 0.8.

Менее автоматизировано, но даёт интуицию того, как cost-функция реагирует на разные $T$.

## Реализация

`generate/annealing.go`:

```go
func EstimateT0(state *SAState, probes int, p0 float64) float64 {
    var sumDelta float64
    var count int
    for k := 0; k < probes; k++ {
        i, j, oldCost := state.RandomSwap()
        delta := state.Cost() - oldCost
        if delta > 0 {
            sumDelta += delta
            count++
        }
        state.Swap(i, j) // откат — калибровка не двигает state
    }
    if count == 0 {
        return 1.0
    }
    mean := sumDelta / float64(count)
    return -mean / math.Log(p0)
}
```
