# Эксперименты SA — журнал результатов

Сквозной журнал всех запусков SA для генерации биективных 8×8 S-блоков. Цель — NL=112, δ=4, deg=7 (уровень AES).

Каждый эксперимент: параметры → результат → вывод → следующий шаг.

---

## Формат записи

| Поле | Описание |
|---|---|
| **ID** | E-NN (порядковый номер) |
| **Дата** | YYYY-MM-DD |
| **Cost-функция** | название + параметры |
| **Schedule** | T₀, α, M, Tmin, MaxIter |
| **Старт** | random / конкретная точка |
| **Best NL** | лучшая нелинейность в прогоне |
| **Итераций** | сколько swap выполнено |
| **Вывод** | что узнали |

## E-01 — HC baseline (2026-05-15)

**Метод:** Hill Climbing, cost = CJS(X=24, R=3)  
**Старт:** random биективная перестановка  
**Итераций:** 100 000

| Метрика | Значение |
|---|---|
| Начальная NL | 96–100 |
| Best NL | **94–104**, медиана ≈ 98 |
| Accepted ratio | ~0.1% |

**Вывод:** HC быстро застревает, медиана 98. Парадокс: cost CJS убывает, но NL может ухудшаться — CJS оптимизирует **распределение** |W|, а NL зависит от **максимума**.  
**Урок:** чистый HC недостаточен. Нужна температура SA для выхода из локальных минимумов.

---

## E-02 — SA + CJS(X=24, R=3) — баг (2026-05-15)

**Метод:** SA  
**Cost-функция:** CJS(X=24, R=3) — **ошибочный параметр** (X=24 случайный, из кода по ошибке)  
**Schedule:** T₀≈2·10⁶ (EstimateT0, p₀=0.8), α=0.99, M=1000, Tmin=1  
**Старт:** random

| Метрика | Значение |
|---|---|
| Initial cost | ~2.54·10⁸ |
| Initial NL | 94 |
| Best NL | **98** |

**Вывод:** SA с неправильным X улучшает немного, но результат плохой. Ошибка в коде: X=24 — произвольное значение, не из литературы.  
**Исправление:** изменить X на 0 (оригинальный CJS 2005 использует X∈{-4,...,4}).

---

## E-03 — SA + CJS(X=0, R=3) (2026-05-16)

**Метод:** SA  
**Cost-функция:** CJS(X=0, R=3)  
**Schedule:** T₀=8.54·10⁵ (EstimateT0, p₀=0.8), α=0.99, M=1000  
**Старт:** random  
**Итераций:** ~1.36M

| Метрика | Значение |
|---|---|
| Best NL | **98** |
| Best cost | 4.05·10⁸ |
| Улучшение cost | ~5% |

**Вывод:** CJS(X=0) имеет неправильный ландшафт для биективных S-блоков. Под ограничением Парсеваля (Σ|W|²=65536, среднее |W|≈16) минимум Σ|W|³ достигается при равномерном |W|≈16, а не разреженном спектре AES. Итог: cost(AES)≈5.35·10⁸ > cost(random)≈4.28·10⁸ — SA движется **от** AES, а не к нему.  
**Урок:** CJS(X=0) структурно неверен для биективных S-блоков 8×8. Нужна другая cost-функция.

→ Подробный анализ: [[fitness-function-sbox#Почему CJS не ведёт к NL=112]]

## E-04 — SA + MinMaxWalsh, короткое расписание (2026-05-17)

**Метод:** SA  
**Cost-функция:** MinMaxWalsh (cost = 256 − 2·NL = max_{b,ω} |W_b(ω)|)  
**Schedule:** T₀≈18 (EstimateT0), α=0.99, M=1000, Tmin=1  
**Старт:** random  
**Итераций:** ~290K

| Метрика | Значение |
|---|---|
| Best NL | **100** |

**Вывод:** правильный ландшафт (монотонная убыль cost с ростом NL), но расписание слишком короткое. T₀≈18 → всего ~287 температурных уровней → алгоритм «замерзает» при Tmin=1 задолго до истощения пространства поиска.  
**Исправление:** уменьшить Tmin до 0.01, увеличить M до 5000.

---

## E-05 — SA + MinMaxWalsh, длинное расписание (2026-05-17)

**Метод:** SA  
**Cost-функция:** MinMaxWalsh  
**Schedule:** T₀≈18, α=0.99, M=5000, Tmin=0.01, MaxIter=10⁷  
**Старт:** random  
**Итераций:** 3.73M

| Метрика | Значение |
|---|---|
| Initial NL | 90–92 |
| Best NL | **100** |

**Наблюдение:** SA замерзает при T<0.5. Cost — целые значения с шагом 2, поэтому P(accept ΔE=+2) = e^{-2/T} < e^{-4}≈0.018 при T<0.5. Полезная оптимизация прекращается на ~1.5M итераций, остальные 2.2M — замороженный спуск.

**Вывод:** ландшафт правильный, NL=100 достигается стабильно. Но NL=100 — локальный оптимум: за него не выйти одиночным SA независимо от длины расписания.

## E-06 — SA + ThresholdNL(112) (2026-05-17)

**Метод:** SA  
**Cost-функция:** ThresholdNL(112) = max(0, 112−NL)  
**Schedule:** T₀≈9, α=0.99, M=5000, Tmin=0.01, MaxIter=10⁷  
**Старт:** random  
**Итераций:** 3.38M

| Метрика | Значение |
|---|---|
| Initial NL | 92–96 |
| Best NL | **100** |

**Вывод:** аналогично E-05. Правильный ландшафт, тот же потолок NL=100. Подтверждает: ограничение не в cost-функции, а в структуре ландшафта S-блоков — принципиальный барьер между NL=100 и NL=112.

## Запланированные эксперименты

### E-07 — HC из лучшего SA (NL=100)

**Гипотеза:** HC из NL=100 (выход SA) даёт лучший результат, чем HC из random start.  
**План:** взять выходное состояние E-05 или E-06 (NL=100), запустить HC по NL, несколько сотен тысяч итераций.  
**Вопрос:** достигает ли HC потолка выше NL=100 из этой стартовой точки?  
**Ожидаемый диапазон:** 100–108 (оптимистично), скорее 100–102.

### E-08 — Multi-start (N=16) + MinMaxWalsh + HC

**Гипотеза:** 16 параллельных SA дадут хотя бы один результат с NL≥102, который HC сможет улучшить.  
**Plan:** `ParallelMultiStartSA(16)` с MinMaxWalsh, взять лучший результат, запустить HC по NL.  
**Метрика успеха:** хотя бы один запуск из 16 даёт NL>100.  
**Ключевой вопрос:** есть ли дисперсия — иногда SA всё же даёт 102?

### E-09 — CJS(X=36, R=4, α=0.95) по MDPI 2022

**Гипотеза:** специально подобранные параметры из литературы дают NL=104 с вероятностью 56.4%.  
**Plan:** `ClarkJacobStepneyNL(36, 4)`, α=0.95, M=650, T₀=20000, один или несколько запусков.  
**Ожидаемый результат:** NL=104 (если параметры воспроизводимы).  
**Риск:** параметры MDPI 2022 не верифицированы нашей реализацией — результат может отличаться.

### E-10 — SA + HC по NL (двухфазный) — ГЛАВНЫЙ

**Гипотеза:** SA находит стартовую точку NL≥100-104, HC по NL дотаскивает до NL=112 (CJS 2005, Table III).  
**Plan:**
1. Фаза 1: multi-start SA (N=16), выбрать лучшую стартовую точку
2. Фаза 2: HC по NL из этой точки, 500K–1M итераций  

**Acceptance критерий:** хотя бы один запуск достигает NL=112.

→ Теория и обоснование: [[sa-for-sboxes#Двухфазный SA + HC — путь к NL=112]]
