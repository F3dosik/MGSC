# Knowledge Base — Криптография: булевы функции и S-боксы

Этот файл описывает структуру и конвенции базы знаний. LLM-агент читает его перед любой операцией с wiki, чтобы поддерживать единообразие.

## Назначение

Персональная база знаний для научной работы по криптографии. Текущий фокус — **генерация S-блоков** методами локального поиска (hill climbing, simulated annealing) и достижение характеристик уровня AES. Сопутствующая теория: булевы функции, их криптографические свойства, преобразования (Уолша-Адамара, автокорреляции), DDT, LAT, и метаэвристики оптимизации.

LLM собирает и поддерживает вики из источников в `raw/`. Общая роль LLM-научрука и где что лежит — в [корневом CLAUDE.md](../CLAUDE.md).

## Структура каталога

```
knowledge-base/
├── CLAUDE.md          # этот файл — схема и конвенции
├── index.md           # каталог всех страниц wiki (что где лежит)
├── log.md             # хронологический журнал ingest/query/lint
├── raw/               # неизменяемые источники (статьи, PDF, заметки)
│   └── assets/        # картинки и вложения к источникам
└── wiki/              # генерируется и поддерживается LLM
    └── entities/      # страницы сущностей (шифры, алгоритмы, авторы, стандарты)
```

## Слои

- **raw/** — источник истины. LLM только читает, никогда не редактирует. Сюда пользователь складывает статьи, PDF, веб-клипы, конспекты лекций.
- **wiki/** — полностью под управлением LLM. Пользователь читает, LLM пишет и обновляет.
- **CLAUDE.md / index.md / log.md** — служебные файлы wiki-уровня.

## Конвенции для wiki-страниц

- Один файл = одна сущность. Имя файла в `kebab-case.md` (например, `aes-sbox.md`).
- Ссылки между страницами — через Obsidian wiki-links: `[[имя-страницы]]` или `[[имя-страницы|подпись]]`.
- В начале каждой страницы — YAML frontmatter:
  ```yaml
  ---
  title: Полное название
  type: entity            # entity (пока единственный тип)
  tags: [крипто, s-box]
  sources: [source-slug-1, source-slug-2]   # ссылки на источники, из которых страница построена
  created: 2026-05-15
  updated: 2026-05-15
  ---
  ```
- В конце страницы — секция `## Источники` со ссылками на конкретные файлы в `raw/` и/или строки.
- Если факт спорный или противоречит другому источнику — отметить inline-блоком `> [!warning] Противоречие: ...` со ссылкой на оба источника.

## Операции

### Ingest (добавление источника)
1. Пользователь кладёт файл в `raw/` (или в подпапку `raw/`).
2. Пользователь говорит: «обработай такой-то источник».
3. LLM:
   - Читает источник целиком.
   - Кратко обсуждает с пользователем ключевые идеи и что стоит выделить.
   - Создаёт/обновляет страницы сущностей в `wiki/entities/`, на которые источник проливает свет.
   - Обновляет `index.md` (добавляет новые страницы, корректирует описания).
   - Дописывает запись в `log.md` с префиксом `## [YYYY-MM-DD] ingest | <название источника>`.

### Query (вопрос к базе)
1. LLM сначала читает `index.md`, чтобы найти релевантные страницы.
2. Затем читает страницы и формирует ответ со ссылками `[[…]]`.
3. Если ответ ценный (сравнение, синтез, новая связь) — спросить пользователя, файлить ли его как новую страницу.
4. Записать в `log.md` с префиксом `## [YYYY-MM-DD] query | <короткая формулировка>`.

### Lint (ревизия)
По запросу пользователя пройтись по wiki и проверить:
- Противоречия между страницами.
- Устаревшие утверждения (более новый источник опровергает).
- Страницы-сироты (нет входящих ссылок).
- Понятия, упоминаемые часто, но без своей страницы.
- Битые `[[ссылки]]`.
- Записать результат в `log.md` с префиксом `## [YYYY-MM-DD] lint | …`.

## Формат log.md

Append-only. Каждая запись:
```markdown
## [YYYY-MM-DD] <ingest|query|lint> | <короткое описание>
- что сделано
- какие страницы затронуты
```

Это позволяет быстро вытаскивать историю через `grep "^## \[" log.md | tail -N`.

## Принципы

- LLM никогда не правит `raw/`.
- LLM не выдумывает факты — только синтезирует из источников. Если факт нужен, а источника нет, оставить TODO-блок: `> [!todo] Нужен источник для: …`.
- Лучше короткая страница с честными пробелами, чем длинная с домыслами.
- Любая нетривиальная правка wiki — через обсуждение с пользователем, не молча.
